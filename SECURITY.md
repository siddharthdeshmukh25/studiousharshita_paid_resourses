# Security Policy

## Supported Versions

This project is currently maintained as a single application release line. Security fixes are applied to the current `0.1.x` line; older or unsupported releases do not receive security updates.

| Version | Supported |
| ------- | --------- |
| 0.1.x   | ✅        |
| < 0.1   | ❌        |

## Reporting a Vulnerability

Please report suspected vulnerabilities privately. On GitHub, open the repository's **Security** tab and use **Report a vulnerability** to create a private security advisory. Do not disclose vulnerability details in a public issue, discussion, or pull request.

If private vulnerability reporting is unavailable, email [support@studiousharshita.com](mailto:support@studiousharshita.com) with the subject **Security vulnerability report**. Include the affected area, steps to reproduce, potential impact, and any proof of concept needed to understand the issue. Do not include real user data, passwords, access tokens, or other secrets.

We aim to acknowledge reports within five business days and provide progress updates at least every seven business days while investigating. We will let you know whether the report is accepted and coordinate remediation and disclosure timing with you. If a report is declined, we will explain the reason when possible. Please allow time for a fix before sharing details publicly.
